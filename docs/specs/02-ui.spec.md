## 3. Navigation and shell

- **Phones:** bottom tabs Home, Records, Passport, Ask. **Desktop:** a top bar with the same four, plus the profile menu.
- **The profile menu** holds: switch profile, add profile, Settings. A profile switch never shows another profile's data, even for one frame (clear cached queries on switch).
- **Routes:** see overview section 11. `/welcome` and `/share/:id` have no navigation.
- **Every route sets `document.title`**, for example "Records · CareVault" (fixes a v1 accessibility finding).
- **Dates:** every date shown uses `todayFor(profileId, deviceToday)` from `src/contract/today.ts`. Remove `src/ui/lib/today.ts`'s own rule.

## 4. Screens

Build four states for every screen: loading (skeleton), empty, ready, error. Words in quotes are the copy to use; keep the tone plain and short.

### 4.1 Welcome (`/welcome`)

As in v1: "Try the sample profiles" (`profiles.loadSampleProfile`) and "Create a profile". The create form adds an optional emergency contact, and the choice "I manage my own records", which hides the caregiver fields and sets relation "Myself".

### 4.2 Home (`/`)

One column on phones, two on desktop:

- **Passport card:** the patient's name and age; the number of medicines being taken; any unconfirmed entries; allergies (state); "Open the passport".
- **Next visit,** if any, with "Prepare for the visit" (goes to the Passport).
- **"Needs attention"** from `attention.list`. Only four kinds can appear, each with one primary action:
  - unverified fields: "Check the values" → `/records/:id/verify`;
  - unassigned import: "Choose whose record this is";
  - possible duplicate ingredient: "Review the products" → passport medicine section;
  - legacy routine review: "Choose the medicines he still takes".

  When the list is empty, show nothing. There is no "everything is done" banner.
- **"Add a record"** (camera or file) and an **"Ask CareVault"** box that opens `/ask` with the question.
- **Recently added records,** the three newest.
- **Gmail status**, when connected this session: "Gmail connected for this session · Check for new reports".

No medicine-status questions ever appear on Home. Skipped or dismissed prescription reviews never appear here.

### 4.3 Records (`/records`)

- **Search** with a single field, plus filter chips:
  - kind, with counts;
  - "Starred";
  - doctor;
  - facility;
  - date range;
  - sort (newest or oldest).

  Results come from `records.search` and show what matched ("Matched: test name"). Typing a question-like phrase ("latest lipid profile") offers "Ask CareVault" with that phrase.
- **Grid and Timeline views,** as in v1. The timeline groups by month of `clinicalDate`, and undated records sit in a final "Date not known" group that shows `addedAt` ("Added 12 Nov from email"). Each item shows its source (camera, upload, email).
- **"Add a record"** goes to the add flow (4.4).

### 4.4 Add a record (`/records/add`)

One flow for camera, photo, PDF and Gmail:

1. **Capture:**
   - "Take a photo" (`<input type="file" accept="image/*" capture="environment">`);
   - "Choose a photo or PDF";
   - "Import from Gmail" (4.10).

   Tips: flat surface, good light, the whole page.
2. **Saved:** `documents.add` runs first.
   - If `duplicate` is returned, show "This file is already in the records (added <date>)" with the choices *Use the existing record*, *Keep both*, *Cancel*.
   - Otherwise say "Saved. Reading it on this device…"
3. **Reading:** `reading.read`, with progress and "Read 2 of 5 pages" when `pagesRead < pageCount`.
   - On `cloud_consent_required`, show the consent panel ("This page is hard to read on the device. Send this one page to the cloud reader?") with *Send this page*, *Retake the photo* and *Enter by hand*.
   - On `locked_pdf`, show "This PDF is password-protected. It is saved; fill in the details by hand."
4. **Details:** kind, title, date on the document (empty when not found, with "Date not known" allowed), doctor and facility.
   - **Doctor:** chosen from `profiles.prescribers`, or **"Add this doctor"**, prefilled with the name read, which calls `profiles.addPrescriber`.
   - **Patient match:** show the patient name read. On `mismatch`: "This looks like a record for <name read>. Is it for <profile name>?" with *Yes*, *It is for another profile* (choose) and *Not ours* (remove).
5. **Check the values:** go to verification (4.6) when any critical field needs it; otherwise offer "File it".
6. **For prescriptions:** after the lines are checked, "Save prescription" calls `prescriptions.save`.
   - If a proposal comes back: "Prescription saved. Some medicines differ from the current routine. Review them now?" with *Review changes* (→ 4.7) and *Not now*.
   - If null: "Prescription saved. No differences with the current routine."
7. **Pack photos:** the flow ends with "Add it to the routine?" with *He takes it*, *Not sure* and *Just keep the photo*. "He takes it" goes through the gate (4.6) and `routine.add` with source `from_pack`.

The original is saved at step 2, so leaving the flow at any later step keeps it as "Not yet filed", reachable from Records and listed on Home only if a field needs verification.

### 4.5 Record detail (`/records/:id`)

- **The original** (pdf.js canvas or image) with page navigation and zoom.
- **The metadata:** kind, tags, tests, doctor, facility, clinical date and its source ("Date from the document", "Date set by you", "Date not known · received by email on …"), patient match, and "Read X of Y pages".
- **Actions:**
  - edit metadata;
  - star;
  - "Check the values" (when needed);
  - "File it" (when pending);
  - delete.
- **Delete:** a confirmation that lists the snapshots mentioning the record and offers to revoke their active links (from `documents.remove`'s result).
- **For prescriptions:** the lines with their verification state, and **"Review changes to the current routine"** (`routine.proposalFor`). This is how a skipped or dismissed review is reopened.

### 4.6 Check the values (`/records/:id/verify`)

The heart of field-level correction.

- **Layout:** the original on one side (on top on phones), the fields on the other.
- **Only fields that are `needs_verification` or `extracted` are shown,** grouped by medicine line. Fields that are already checked collapse into "6 values already checked".
- **Each flagged field shows:**
  - a plain title ("Strength not clear");
  - the literal value read (`raw`, for example `6?0 mg`) in a monospace chip;
  - the reasons;
  - the page it came from, with "Show on the original" (jumps the viewer to that page; when a region is known, highlight it).
- **Actions per field:**
  - *Correct* (an input with unit select for strengths);
  - *It is right* (confirm);
  - *Leave unknown*;
  - *Retake the photo* (back to capture for this record, keeping all decisions).
- **Saving** calls `documents.reviewFields` with all decisions at once.
- **The gate:** when a review choice needs values from an unverified line, the review screen sends the user here with a return link ("Check this strength, then come back to the review"). Never let a button in the review silently write an unverified value; if the core returns `verification_required`, route here.

### 4.7 Review changes (`/records/:id/review`)

From a `RoutineProposal`. Title: "What changed on this prescription". Subtitle: "Dr. Kavita Rao · 13 Nov 2026. Nothing changes until you choose."

- **One card per asked row,** in this order: `changed`, `new`, `not_mentioned`, `uncertain_match`. Each card has the pill, the current routine value on the left, the prescription value on the right, and the question:
  - `changed`: "Is he taking Telmisartan as on this prescription?" *Yes, he has started 80 mg* · *No, still 40 mg* · *He is not taking it* · *Not sure, ask the doctor* · *Skip*.
  - `new`: "Has he started taking Aspirin?" *Yes, he takes it* · *Not started yet* · *He is not taking it* · *Not sure, ask the doctor* · *Skip*.
  - `not_mentioned`: "Atorvastatin was not on this prescription. That does not mean it should be stopped. Is he still taking it?" *Yes, still taking* · *No, he has stopped* · *Not sure, ask the doctor* · *Skip*.
  - `uncertain_match`: "These may be the same medicine, but CareVault could not confirm it." Both sources side by side · *Same medicine* · *Different medicine* · *Not sure, ask the doctor* · *Skip*.
- **Use the pronouns** from the profile relation (`src/ui/lib/pronouns.ts`); "you" when the relation is "Myself".
- **"No change" rows** collapse into one line: "2 medicines are the same as in the routine". `passiveNotMentionedCount` becomes one passive line: "3 other medicines in the routine are not on this prescription. Nothing changes for them." Neither has buttons.
- **Blocked rows** (`blockedByVerification`) show "Check the strength first" instead of the choices that write values, linking to 4.6. *Not sure*, *Skip* and *He is not taking it* remain available.
- **Choices** are held on screen and sent together with "Save these choices" (`routine.decide` with `expectedRevision`). *He has stopped* and *He is not taking it* ask for confirmation first.
  - On `stale`, show "The routine changed since this review was prepared", reload the proposal, and keep the user's choices where the rows still match.
- **"Not now"** dismisses (`routine.dismiss`); the review stays reopenable from the record page.
- **After saving:** a summary ("Telmisartan updated to 80 mg. Aspirin added. Atorvastatin unchanged.") and an Undo for each change, using `routine.undo` on the events created.

### 4.8 Passport (`/passport`)

The live passport, plus the routine, which is edited here.

- **Header:**
  - the patient strip (name, age, emergency contact);
  - the next visit, or "Add the next visit" (prescriber, date, time; "Add a doctor" when there is none);
  - the actions *Print or save as PDF*, *Share with QR* and *Save a snapshot*.
- **Current medicines** (`taking`): name, ingredients, how it is taken, source label ("Reported by Anjali", "From a prescription", "From the pack"), "Last confirmed 30 Oct". Each opens `/passport/medicines/:id`.
- **"Current use not confirmed"** (`uncertain` and legacy pending), with "Still taking" / "Stopped" per entry. When legacy entries are pending, show the batch "Choose the medicines he still takes" (`routine.resolveLegacy`). It never blocks printing.
- **"Add a medicine he takes"** (manual entry, `routine.add`, source caregiver- or patient-reported). Being one action away matters.
- **Possible duplicate ingredients:** the v1 duplicate card (products side by side, the total if complete, the fixed sentence). The wording follows overview section 9.5.
- **Allergies and history** (`health.*`): allergies with the three states (listed / "No known allergies" / "Not recorded"); conditions; procedures. Add and remove.
- **Recent changes:** from the routine history (last 90 days).
- **Questions for the doctor** (add, remove) and **Reports to share** (checkbox list of filed documents, starred first).
- **"Earlier passports":** `passport.snapshots`, newest first, as "Passport 3 · 14 Nov 2026 · printed". Each opens `/passport/snapshots/:id`.

### 4.9 Medicine detail (`/passport/medicines/:id`)

Fields, source, prescriber, source document link (handles a removed document), and the history from `routine.history` with before and after values per event. Actions: edit, set status, Undo on the latest event (`routine.undo`; on `stale` show "A later change was made; see the history").

### 4.10 Gmail import (inside 4.4 and Settings)

- *Connect Gmail* (call `gmail.connect` straight from the tap).
- Then a list of `gmail.findCandidates(profileId)`: **one row per PDF attachment** with subject, sender, received date, file name and "Already imported" when true.
- The user selects rows and imports; each runs `gmail.importAttachment` and joins the add flow at step 2.
- Show the CloudNotice "Reading your inbox for report attachments" while Google is contacted.

### 4.11 Snapshot, print and share

- **`/passport/snapshots/:id`:** `PassportView` of a frozen snapshot, with "Passport 3 · prepared 14 Nov 2026". Documents removed since show "Original removed on <date>". Actions: print, share.
- **Print:**
  - first call `passport.snapshot(profileId, 'print')`, then open `/passport/print/:snapshotId`;
  - print styles fit one A4 page where possible and continue on more pages rather than hide safety information (allergies, unconfirmed entries, flags);
  - the printed QR is only shown when a share link exists for **that** snapshot;
  - the print view lists which report titles are included and says "Original files are not included in the link".
- **Share:**
  - `passport.snapshot(profileId, 'share')`, then `sharing.create(snapshotId, hours)` with expiry 2, 8 or 24 hours;
  - show the QR, expiry, Copy link and Revoke;
  - the active links come from `sharing.list(profileId)`;
  - never pick a QR from a link list by expiry (a v1 privacy bug);
  - state clearly: "The passport is encrypted on this device. Anyone with the link can read it until it expires."
- **`/share/:id`:** as in v1 (no navigation, no analytics). It shows the snapshot read-only with its revision and date, and the states loading, expired, revoked, not found and missing key.

### 4.12 Ask (`/ask`)

- **A text box** with example chips:
  - "Latest lipid profile";
  - "Prescriptions from the cardiologist";
  - "Last three HbA1c reports";
  - "What questions did I save?";
  - "What medicines does he take?"
- **The answer** comes from `records.ask`: the `interpretedAs` sentence ("Looking for: latest lab report with Lipid profile"), the factual `text`, and the results as cards that open the record (or the passport section). Each result shows date, facility and source.
- **When `understood` is false:** "CareVault can search your records by test, doctor, place and date. Try: …"
- **The footer** says: "Answers come from the records on this device. CareVault does not give medical advice."
- **No chat history, no model.** Keep this simple and honest.

### 4.13 Settings (`/settings`)

- Profiles (edit, emergency contact, add, switch).
- Doctors per profile (list, add).
- Cloud reading (as v1).
- Gmail (connect for this session).
- Backup (save and restore, as v1, with the version note "Backups made with earlier versions can still be restored").
- **"Older share links"** from `sharing.listUnowned()`, each revocable.
- Sample data (load).

## 7. Accessibility and copy rules (throughout)

- Every input has a visible label. Errors are linked with `aria-describedby`, and focus moves to the first invalid field.
- Status is never shown by colour alone.
- Dialogs trap focus and close on Escape.
- Toasts with Undo stay at least 5 seconds and are announced politely.
- Text sizes and contrast follow the design system (minimum 13 px, 4.5:1).
- **Copy:** plain words; "possible", "please verify with a pharmacist or the prescriber". Never "safe", "unsafe", "overdose", "you should", "interchangeable". Never suggest stopping or starting a medicine.

## 8. Error messages (`toServiceError`)

Map each v2 code to caregiver-ready text:

- `not_configured`: "This feature is not set up on this copy of CareVault yet."
- `network`: "CareVault could not reach the server. Check the connection and try again."
- `stale`: "The routine changed since this was prepared. It has been refreshed."
- `verification_required`: "Check the highlighted value first."
- `locked_pdf`: "This PDF is password-protected. It is saved; fill in the details by hand."
- Any other code: the message from the core.

Never show status codes or setting names.
