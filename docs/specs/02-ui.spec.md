# CareVault: UI spec (laptop B, branch `feat/ui`)

Read `00-overview.spec.md` first. This file covers everything the user sees: design system, app shell, every screen, motion, states, accessibility, the PWA shell and the mock services you build against. You never import from `src/core`; you call `services` from `src/services` and nothing else.

## 1. What you own

```
src/ui/**      src/main.tsx      index.html      public/** (except public/sample-docs)
README.md      docs/progress-ui.md      docs/contract-requests-ui.md
```

You also run Phase 0 on `main`, which creates the scaffold and the frozen files (`src/contract/**`, `src/services/index.ts`, `package.json`, `tsconfig*.json`, `vite.config.ts`, `.env.example`). After Phase 0 you never edit them.

Your export to the rest of the app:

```ts
// src/ui/mock/createMockServices.ts
import type { CareVaultServices } from '../../contract/services';
export function createMockServices(): CareVaultServices { /* in-memory, from the fixtures */ }
```

The mock implements every method of the contract in memory, starting from `src/contract/fixtures/sampleCase.ts`, with a 300 to 800 ms artificial delay so loading states are visible. It applies simple versions of the behaviour rules (resolving a review item changes the medicine status, starring toggles, adding a question appends). It can be told to fail: `localStorage.cvMockFail = 'reading'` makes `reading.read` reject, so error states can be built and checked.

## 3. Design system

Design goal: calm, trustworthy, readable by a tired caregiver on a phone. Large type, one accent colour, plain cards, generous spacing. No decorative gradients, no glass blur over text, no emoji.

### Type

Manrope 700 for headings, Inter 400/500/600 for everything else, self-hosted through `@fontsource` so the app works offline.

| Role | Size / line height |
| --- | --- |
| Page title | 44 / 1.15 desktop, 28 / 1.2 phone |
| Section title | 26 / 1.2 desktop, 22 phone |
| Card title | 22 desktop, 19 phone, weight 600 |
| Body | 17 / 1.5 desktop, 16 phone |
| Secondary | 15 or 16 |
| Pill | 14, weight 600 |

Minimum text size anywhere: 13 px. Text contrast at least 4.5:1.

### Shape and spacing

Radii: cards 24 (20 on phone), inner panels 16, buttons 12, primary call-to-action 16, pills 999. Spacing steps of 4; card padding 28 desktop, 18 phone; page gutter 40 desktop, 20 phone; content max width 1240. Shadows: one soft level for cards (`0 2px 10px rgba(18,48,47,0.05)`), one for the primary call-to-action. Touch targets at least 48 px high.

### Components to build once (`src/ui/components`)

Button (primary, secondary, quiet, danger; loading state), Pill, Card, SectionHeader, StatTile, ReviewCard, MedicineRow, DiffRow, DocumentCard, TimelineItem, EmptyState, Skeleton, ErrorPanel (with retry), Toast, Dialog, Sheet (bottom sheet on phone, side panel on desktop), ConfirmDialog, Field (label, input, hint, error), Checkbox, SegmentedControl, FileDrop, SourceViewer (image or PDF page beside extracted fields), ProfileSwitcher, TopNav, BottomTabs, CloudNotice.

Use real `<button>`, `<a>`, `<input>` with `<label>`. Icon-only buttons have `aria-label`. Dialogs trap focus and close on Escape.

## 4. Motion

Use Motion for React. Motion supports understanding; it never delays reading.

- Page transition: fade plus 8 px rise, 200 ms.
- Lists and card grids: stagger 40 ms per item, first paint only, capped at 8 items.
- Review card resolved: card collapses (250 ms), toast confirms with Undo for 5 seconds.
- Dialog and sheet: scale 0.98 to 1 with fade, 180 ms; sheet slides up on phone.
- Buttons: 0.98 scale on press.
- Diff rows reveal as they scroll into view, once.
- Numbers on stat tiles count up once, under 600 ms.
- Skeletons pulse gently.
- `prefers-reduced-motion`: all of the above become simple fades or nothing. Put the presets in `src/ui/app/motion.ts` and read the preference in one place.

No parallax, no looping animation, nothing that moves while the user reads.

## 5. Data access pattern

```ts
// src/ui/hooks/useServiceQuery.ts
// Runs an async services call, returns { data, loading, error, reload },
// and re-runs when services.subscribe() fires.
const { data: items, loading, error } = useServiceQuery(
  () => services.review.listOpen(profileId), [profileId]);
```

Writes go through a small `useServiceAction` hook that tracks pending state, shows a success toast, and shows an error toast with the `ServiceError` message on failure. The current profile id lives in a React context and in `localStorage`.

## 6. App shell

- Desktop (768 px and up): top bar with the CV mark and "CareVault", navigation pills (Review, Medicines, Records, Visit), profile switcher at the right.
- Phone: compact top bar (mark, name, profile chip) and a bottom tab bar with the four sections, icon above label.
- `/share/:id` and `/welcome` render without the shell.
- A slim banner appears whenever data is about to leave the device (see CloudNotice in section 8).

## 7. Screens

For every screen, build four states: loading (skeleton), empty, ready, error.

### 7.1 Welcome (`/welcome`)

Shown when there is no profile. One sentence on what CareVault does, one on where data is kept ("on this device"). Two actions: "Try the sample profile" (`profiles.loadSampleProfile`) and "Create a profile" (name, relation, birth year, caregiver name and relation).

### 7.2 Review (`/`)

As in `CareVault-Main.png`:

- Date line, greeting with the caregiver's first name, one sentence stating how many things need an answer and before which visit.
- Primary action "Prepare for the visit", linking to `/visit`.
- "Things to review": one ReviewCard per open item, with the pill, a question as the title, a short body and the actions for its kind:
  - `confirm_medicine`: Still taking, Stopped, Ask the doctor, View both prescriptions
  - `possible_duplicate`: Review both products (goes to the duplicate card on Medicines)
  - `new_document`: Add to records, Open the PDF, Not his/hers
  - `unclear_extraction`: View the original
- Side column: Next visit panel (dark teal), "Since the last visit" tiles from `visits.changeSummary`.
- "Recently added records": the three newest documents.
- Empty state: "Nothing needs your review" with the next visit and a link to scan a medicine.

"Stopped" asks for confirmation in a ConfirmDialog ("Mark Atorvastatin 10 mg as stopped? You can change this later."). Every resolution shows a toast with Undo.

### 7.3 Medicines (`/medicines`)

As in `CareVault-Medicines.png`:

- Title, one-line explanation, "Scan a medicine" action.
- Four StatTiles: confirmed current, needs confirmation, possible duplicate, previous or stopped.
- Possible duplicate card per item from `medicines.ingredientTotals`: the products side by side, the total panel ("If both are taken as entered", the total, the sum written out). If `complete` is false, show "Add how often each is taken to see a total" instead of a number. Fixed sentence under it: "CareVault adds up what was entered. It does not judge whether a dose is safe. Please verify with a pharmacist or the prescriber." Actions: "Add to questions for the doctor", "He only takes one of these" (opens a choice of which one).
- Needs confirmation list, Found at home list (action: "Confirm he takes this"), Confirmed current table (medicine, how it is taken, prescribed by, last change, "View source"), Previous or stopped cards.
- On phone, the table becomes stacked cards.

### 7.4 Scan a medicine (`/medicines/scan`)

Steps: capture, reading, confirm, done.

1. Capture: "Take a photo" (`<input type="file" accept="image/*" capture="environment">`) or "Choose a file". Tips: flat surface, good light, composition text visible.
2. Reading: progress with the line "Reading on this device". If the service rejects with `cloud_consent_required`, show a panel: "This photo is hard to read on the device. Send it to the cloud reader?" with "Send this photo" and "Enter by hand". Sending shows the CloudNotice.
3. Confirm: SourceViewer on one side (phone: on top), editable fields on the other: product name, each ingredient with strength and unit, form, how many per day, instruction. Fields from extraction carry the "Check this" marker until touched or confirmed. Warnings from the extraction appear under the field. Actions: "Save as found at home", "Save and confirm he takes it".
4. Done: success state, with "Scan another" and "Go to Medicines". If saving created a duplicate flag, say so here with a link.

The same confirm step is reused for prescription lines.

### 7.5 Medicine detail (`/medicines/:id`)

Name, pills, ingredients, instruction, prescriber, source document link, and a history timeline from `medicines.history` (date, event in words, link to the document). Actions depend on status: confirm, mark stopped, edit.

### 7.6 Records (`/records`)

A calm vault:

- Search field (title and type), category chips with counts (All, Prescriptions, Lab reports, Tests, Discharge summaries, Other), a "Starred" toggle, view switch: Grid or Timeline.
- Grid: DocumentCards with a first-page thumbnail (PDF page 1 or the image), type tag, title, date, source, state. Pending documents carry "Not yet confirmed".
- Timeline: grouped by month, newest first, one line per document with an icon by type; prescriptions show "2 medicine changes found" when a diff exists.
- Upload: "Add a record" opens a Sheet with FileDrop. States: selecting, reading, "Looks like a prescription from Dr. X dated Y" with editable type, title, date and prescriber, saving, saved. If `add` returns `duplicateOf`, show "This looks like a file you already added on <date>" with Keep both and Discard.
- A prescription upload continues into the line-confirm step (7.4 step 3, one card per line) and then calls `prescriptions.apply`, ending on the comparison view.
- Empty state invites the first upload and mentions Gmail import in Settings.

### 7.7 Document detail (`/records/:id`)

Preview (pdf.js canvas for PDFs, image otherwise) with page navigation and zoom, metadata, star toggle, confirm (if pending), delete with confirmation. For a prescription: its lines and a link to the comparison.

### 7.8 Visit (`/visit`), appointment mode

As in `CareVault-Changes.png`:

- Dark pill "Appointment mode" with the visit date and time; title "What changed since the last visit"; one sentence naming the prescriber and that other doctors' medicines are not compared.
- Two date tiles (Previous, Latest) linking to the scans.
- One DiffRow card per row of `prescriptions.latestDiff`: left cell previous, right cell latest, with the pill. Changed values are highlighted on the right and struck through on the left. `review` rows carry the three answer buttons. Order: added, changed, review, unchanged.
- Side column: Questions for the doctor (list, remove, add with a labelled input), Reports to share (checkbox list of confirmed documents, starred first), status panel ("1 item still needs your answer") with "Open the Doctor Visit Passport".
- No next visit: a form to add one (prescriber, date, time). No previous prescription from that prescriber: show the latest prescription as all "added" with a sentence explaining why.

### 7.9 Doctor Visit Passport (`/visit/passport`)

As in `CareVault-Passport.png`: a single page from `visits.buildPassport`. Header with title and visit line; patient strip; current medicines table; changes list with pills; flag box; reports shared; questions; footer disclaimer ("Prepared by a family caregiver from records they confirmed. This page lists what was entered; it is not a clinical record and gives no medical advice.").

Toolbar (hidden in print): Print or save as PDF (`window.print()` with a print stylesheet sized for A4), Share with QR.

Share dialog: choose expiry (2, 8, 24 hours), "Create link", then show the QR code, the expiry time, Copy link, and Revoke. State clearly: "The passport is encrypted on this phone. The link holds the key; anyone with the link can read it until it expires." List active links with revoke buttons.

### 7.10 Shared view (`/share/:id`)

Public page with no navigation. Reads the key from `location.hash`, calls `sharing.open`. States: loading, the passport (same layout, read-only), expired, revoked, not found, missing key. No analytics, no external requests.

### 7.11 Settings (`/settings`)

Profiles (switch, add), Cloud reading (toggle with a plain explanation of what is sent and when), Gmail import (Connect, then a list of candidates with Import buttons; explain that access lasts for this session only), Backup (export with passphrase, import with confirmation that it replaces current data), Sample data (load again), About (data stays on this device; not medical advice).

## 8. Privacy cues

CloudNotice: a small persistent banner with an upload icon and a sentence, shown whenever a request carries user data off the device: "Sending this photo to the cloud reader", "Reading your inbox for report attachments", "Uploading the encrypted passport". It appears before the request starts and stays until it ends. On-device work says "On this device".

## 9. Responsive rules

Mobile-first. Check at 390, 768 and 1280 px wide. Two-column pages collapse to one column under 900 px with the side column moving below the main content, except the Visit status panel, which becomes a sticky bottom bar on phone. Tables become stacked cards under 768 px. Nothing scrolls sideways except an image being zoomed.

## 10. Accessibility

Keyboard reachable everywhere with a visible focus ring; landmarks (`header`, `nav`, `main`); one `h1` per page; form errors linked with `aria-describedby`; toasts in an `aria-live="polite"` region; dialogs labelled; colour never the only signal; respects reduced motion; works at 200% zoom.

## 11. PWA shell

Web app manifest (name CareVault, short name CareVault, theme colour `#0B6E6E`, background `#F2F6F6`, icons 192 and 512 with the CV mark), service worker through `vite-plugin-pwa` precaching the app shell so it opens offline. Do not cache `/api` responses.

## 12. Tests

- Component tests (Vitest and Testing Library) for ReviewCard actions, DiffRow rendering of each kind, the confirm form (extracted markers clear on confirm), the duplicate card with complete and incomplete totals.
- One smoke test per screen that renders against the mock and finds the page title.

## 13. UI definition of done

- Every screen in section 7 exists with loading, empty, ready and error states.
- With `VITE_USE_MOCK=true`, the app matches the five mockups for the sample profile.
- The demo path can be clicked through end to end on a 390 px wide screen.
- `npm run check` passes.
- No import from `src/core` anywhere under `src/ui` (enforce with an ESLint rule or a test that greps).
